# Asgard Brigitte 1.0.9

Windows x64; Microsoft Store package version `1.0.9.0`.

## Changes

- Drag a bug card directly into another status lane without switching modes. Valid targets are highlighted, a card shadow follows the pointer, and the board scrolls near its edges.
- Each card has a dedicated **View details** button. Clicking the card body no longer opens its detail window; copying IDs and repair prompts remains available separately.
- After a drop, the client claims a short-lived work lock, checks the latest status, changes the status, and releases the automatic lock. Existing manual claims stay held. Foreign locks and read-only workspaces prevent dragging while keeping details available.
- Required explanations, deployment steps and explicit human verification remain part of the existing workflow. Cancelling a drag or explanation does not claim a lock or change a status.
- Failed status changes still attempt to release the automatic lock. Release failures remain visible across background refreshes; automatic locks expire within one minute.

## Validation and distribution

- All 221 Core/UI tests passed with synthetic data, isolated temporary SQLite databases and offline HTTP transports.
- Windows Release build passed with no warnings or errors.
- Repeatable browser checks exercised the production Razor components: direct dragging, detail buttons with mouse and keyboard, required explanations, human confirmation, foreign/manual locks, read-only access, prompt buttons, edge scrolling, cancellation, filtering and handler disposal/reinitialization. English, Chinese, light and dark layouts were inspected.
- This release uses the existing service endpoints and needs no service deployment or database migration.
- Store certification, Store-signed installation/upgrade, Windows App Certification Kit checks and native MAUI/WebView2 runtime acceptance remain separate from these local test/build results. They are not established by a successful build or upload. The Store upload package is unsigned for Microsoft to sign.

Package checksum and exact source revision are recorded in the local `publish/store/1.0.9.0/candidate.json`. The final Store submission outcome is recorded in [the submission log](../../packaging/windows/store-submission.md).
