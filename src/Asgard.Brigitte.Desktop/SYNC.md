# 桌面同步协议 v1

本文仅适用于在线模式。本机模式使用独立的 `local-workspace/workspace.sqlite` 作为业务事实库，不参与本协议、不获取在线身份、不上传或合并数据。每次启动的欢迎页提供本机使用和在线登录入口。

Brigitte 服务是业务事实来源。桌面从 SQLite 投影读取列表、详情、统计和搜索结果；创建、修改和删除通过在线 API 提交，再通过认证的 SignalR WebSocket 确认。客户端不离线排队、不直接修改业务投影，也不自动重放写请求。

协议数据类型位于本仓库的 `src/Asgard.Brigitte.Sync/`，无服务端项目依赖。服务端实现由独立仓库维护。

## 连接与清单

同步端点为 `/api/brigitte/sync`，使用已验证用户的访问令牌并强制 WebSocket。授权范围由服务端决定。

客户端通过 `Manifest(version, stamps)` 分批提交记录键与 SHA-256 内容指纹，每批最多 64 条。清单不包含业务正文。`Synchronize` 返回持续的数据流，对照有权限的记录推送新增、变更和删除。空清单触发首次全量同步；重连时使用本地实际数据重新计算清单。

`SyncProtocol.Version` 当前为 `1`。记录键采用 `kind/id`，指纹是 UTF-8 JSON 正文的 SHA-256 十六进制值；完整游标包含协议版本及按 ordinal 顺序排列的记录键、指纹。序列化采用 `JsonSerializerDefaults.Web`。改变格式、排序或算法需要与服务端共同处理兼容性。

## 批次格式

`SyncFrame` 提供 `phase`、`batchId`、`baseCursor`、`cursor`、`total`、`replay`、`rows` 和 `receipts`。

```text
begin → rows … → commit
```

每条 `SyncRow` 包含 `key`、`hash`、`json`。`json = null` 表示删除。同步数据包括授权项目、BUG、回复、历史、附件元数据、本人 MCP Key 元数据和提示词投影；不包含附件正文、访问/刷新令牌、Key 明文或服务端哈希凭据。邀请摘要按需在线读取，不加入通用投影。

客户端将批次写入暂存表，校验数量、记录指纹、基线与完整游标，再用单个 SQLite 事务合并记录、删除、游标和本地动态。只有提交成功后才通知界面。掉线或不完整批次会回滚，保留先前提交的投影。

## 命令确认

HTTP 写请求成功后，客户端通过 `Checkpoint(receipt)` 等待同步屏障。服务端在处理屏障后读取授权快照并返回对应回执。客户端完成相应 SQLite 提交后，操作才结束等待。

HTTP 成功但 WebSocket 中断时，界面显示已在线保存并等待同步。重连只重发屏障，不重新发送原写请求。HTTP 失败不修改本地投影，界面也不把 HTTP 返回的业务对象当作同步快照。

## 身份与离线边界

SQLite 文件按服务地址、租户和已验证用户隔离。每次进程启动或切换账号，需重新验证身份并完成首批同步后才开放工作区。运行期间断线可阅读已有投影，在线命令禁用。身份失效关闭业务窗口；权限收回由删除项移除本地记录。

附件正文通过 `GET /api/brigitte/bugs/{bugId}/attachments/{attachmentId}` 按需获取，并仍由服务端校验权限。首次快照和重连补差不会批量生成通知；正常已提交变更可生成未读动态和平台通知。

## 兼容服务要求

服务端需提供兼容的 REST 端点、SignalR 方法、同步记录及认证受众，反向代理需转发该路径的 WebSocket Upgrade。客户端不使用 REST 列表轮询来替代同步。

公开仓库中的测试覆盖批次、回滚、本地投影、会话隔离和组件行为；真实服务端的权限、租户隔离和端到端 WebSocket 集成由服务端仓库另外验证。
